# Widget Audit - 2026-06-07

Commands were run from `adamant-ModpackLib`.

## Commands

```powershell
rg -n "widgets|uiDraw|draw\.widgets|packedDropdown|packedRadio|confirmButton|inputText|steppedRange" tests src docs API.md
rg -n "opts\.id|opts\.label|opts\.tooltip|opts\.visibleValues|visibleValues|opts\.controlWidth|opts\.value|opts\.action|opts\.color|opts\.selectionMode|opts\.filter" src\core\widgets src\def.lua docs\module-authors\capabilities\WIDGETS.md API.md
```

## Findings

- `fix`: `draw.widgets.inputText(...)` documented an `id` option, but the
  implementation always used `field:controlId()`. The widget now honors
  `opts.id`, matching dropdowns and steppers.
- `fix`: `def.lua` was missing several option fields that were already
  implemented and documented: `InputTextOpts.id`, `InputTextOpts.labelWidth`,
  dropdown `labelWidth`, packed dropdown `labelWidth`, and scalar choice
  `visibleValues`.
- `keep`: packed dropdown/radio still render packed schema children directly.
  They do not document `visibleValues`, so no hidden-choice contract exists for
  packed child refs yet.
- `keep`: widget leaf files are intentionally small renderers; common policy
  remains concentrated in `widget_helpers.lua` and the draw-surface binding in
  `ui_draw.lua`.

## Result

Widget behavior and author-facing LuaCAT/docs are aligned for the current
surface. No broader restructuring is needed in this pass.
