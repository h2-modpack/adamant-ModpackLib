# Overlays Audit

## Commands

```powershell
rg --files src\core\overlays tests docs | rg "overlays|Overlays|OVERLAYS"
rg -n "overlay|overlays|suppress|retained|afterHook|onInterval|onCommit|createLine|createTable" src tests docs API.md
rg -n "runtime\.status|runtime\.controls|overlays\.onCommit|overlays\.onInterval|overlays\.afterHook" ..\Submodules -g "*.lua"
```

## Scope

- Retained overlay declaration collection and replay.
- Module overlay installation, promotion, rollback, and after-hook receipts.
- Retained line/table rendering and `middleRightStack` layout.
- Global UI overlay suppression used by Framework and fallback UI.
- Framework overlay facade and Framework HUD hash marker usage.
- Module-author overlay docs, API docs, and overlay tests.

## Findings

- `fix`: module overlay callbacks rebuilt a partial runtime context from
  `store`, while the managed module already owns the full runtime context. This
  meant overlay callbacks did not reliably receive the same `runtime.status` and
  `runtime.controls` surface documented for runtime callbacks. Overlay retained
  registries now retain `record.runtime` directly.
- `fix`: `overlays.installForModule(module, store)` still accepted a `store`
  argument from the older adapter shape. The adapter now derives everything from
  the managed module record and accepts only `module`.
- `keep`: explicit/system overlays are intentionally narrower than module
  overlays. They expose `createLine(...)` and `onCommit(...)` only, and receive
  `(overlay, commit)` rather than module callback objects.
- `keep`: module overlays are not automatically hidden by Lib when a module is
  disabled. Projection callbacks receive `host.isEnabled()` and committed
  runtime state, so modules can decide whether to clear, hide, or keep retained
  display state on disable. LiveSplit already follows this pattern.
- `keep`: system overlays remain trusted first-party infrastructure rather than
  a general transactional owner surface. The known-limits doc already captures
  that boundary.

## Coverage

- `TestOverlays` covers HUD component creation, stacked-row ordering bands,
  table column layout, and global UI suppression.
- `TestOverlays_Retained` covers system overlay projection, omitted
  declarations, table row caps, module callback shape, visibility callback
  shape, late declaration rejection, commit ordering, staging, hot reload,
  interval dispatch, after-hook return arity, and rollback.
- The retained callback-shape test now asserts `runtime.status` is available in
  module overlay callbacks.

## Result

The overlay subsystem is coherent after the runtime-context cleanup. Remaining
complexity is inherent to retained HUD ownership and hot-reload rollback rather
than migration residue.
